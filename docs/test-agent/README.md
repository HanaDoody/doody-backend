# Doody 보상 테스트 에이전트 결과

기존 Spring Boot 보상 서비스의 테스트를 생성하고, 실제 실행 결과를 받아 검증하는 CLI 에이전트를 구현했다.

## 검증 결과

| 항목 | 결과 |
| --- | --- |
| 생성한 보상 서비스 테스트 | 20개 통과 |
| HTTP 계약 테스트 | 4개 통과 |
| 기존 테스트 포함 전체 빌드 | 35개 통과, 실패·건너뜀 0개 |
| 실행기·API 어댑터 테스트 | 7개 통과 (API는 모의 응답) |
| API 문서 | 두디 잡기 API 1개 생성 |
| 선택한 결함 주입 평가 | 정상 복사본 통과, 오류 5종 모두 탐지 |
| 서비스 구현 변경 | 없음 |

## 구현한 흐름

모델이 관련 파일을 탐색하고 명세와 실제 코드의 계약을 읽는다. 테스트를 작성한 다음 실행기가 Gradle을 실행하고, 종료 코드·JUnit XML·실패 내용을 모델에 전달한다. 모델이 다음 행동을 선택하고 실행 기록과 최종 보고서를 남긴다.

테스트는 금액 제한, 출처 기록, 중복 수집 방지, 템플릿 기본값과 명시 값, 기존/신규 연락처 처리 및 저장 실패 전파를 다룬다. 실패를 숨기기 위해 서비스 코드를 자동 수정하는 도구는 제공하지 않는다.

## 평가에서 주입한 오류

1. 0·음수 포인트의 저장 금지 조건 제거: 테스트 3개 실패.
2. 중복 수집 방지 조건 제거: 테스트 1개 실패.
3. 기본 등급을 잘못된 상수로 변경: 테스트 1개 실패.
4. 포인트의 출처 ID 누락: 테스트 1개 실패.
5. 연락처의 축을 잘못된 값으로 변경: 테스트 1개 실패.

모두 원본과 분리한 프로젝트 복사본에서 수행했다. 실제 서비스에 존재하던 버그 5개를 발견했다는 뜻은 아니며, 일반적인 탐지율 100%를 의미하지 않는다.

## 현재 연결 방식

이번 검증은 현재 대화 모델이 JSON 도구 행동을 선택하고 로컬 CLI가 실행하는 세션 모드로 진행했다. 별도 API 키 없이 무인으로 실행한 것이 아니다. OpenAI API 자동 연결 코드는 구현했지만 실제 API 호출은 미검증이다. 첫 테스트부터 통과했으므로 실패를 모델이 자동으로 고쳤다는 실적도 없다.

DB·동시성·AWS·안드로이드 통합은 이번 평가 범위에 포함되지 않는다. 다음 단계에서 API 키를 로컬 환경에 설정하면 자동 모드를 실제 호출로 검증할 수 있다.
